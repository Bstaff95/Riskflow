# Riskflow Customer Discovery

This document defines how CEO mode should learn from users. It is business
learning memory, not validation proof and not runtime authority.

## Purpose

Riskflow cannot become a real business only by improving internal research
artifacts. CEO mode must test whether a specific user has a painful workflow
that Riskflow can make faster, clearer, or more profitable to reason about.

The current customer thesis is:

- first user: serious discretionary crypto trader or researcher;
- first workflow: high-beta chart triage and watchlist prioritization;
- first value: faster relative-leadership interpretation with evidence-backed
  warning and reset context;
- first package: research-grade TradingView companion plus local scanner output.

This is a hypothesis until interviews, workflow reviews, or paid/manual usage
show repeated pain.

## Discovery Questions

Use these questions in calls, notes, or synthetic planning. Do not lead with
Riskflow features.

1. How do you currently decide which crypto charts deserve attention today?
2. What takes the most time in that process?
3. What do you compare a chart against before deciding it is strong or weak?
4. When do you usually discover a move was late, extended, or a false start?
5. What tools, indicators, Discord groups, screeners, or dashboards do you use?
6. What do those tools fail to explain?
7. What makes you ignore a chart that looks exciting?
8. What would make a watchlist or chart note worth paying for?
9. Show a recent chart decision that was difficult or wrong.
10. What would have made that decision easier before the outcome was obvious?

## Evidence Levels

- `L0_assumption`: internal belief, no user evidence.
- `L1_conversation`: one user described the pain.
- `L2_repeated_pain`: three or more similar users described the same pain.
- `L3_workflow_observed`: CEO mode reviewed an actual triage workflow,
  watchlist, chart process, or report usage.
- `L4_manual_value_delivered`: Riskflow output helped a real user make a
  clearer watchlist, wait/avoid decision, or setup-quality judgment.
- `L5_willingness_to_pay`: user asked to keep receiving it, paid, or gave a
  concrete price range tied to the workflow.

Do not treat compliments, curiosity, or social-media interest as product-market
fit.

## Interview Log Format

Every customer-discovery note should capture:

- date;
- user type;
- current workflow;
- painful moment;
- current alternatives;
- exact language the user used;
- Riskflow output shown, if any;
- value signal;
- willingness-to-pay signal;
- objection;
- follow-up action;
- evidence level;
- assumption changed.

Store curated notes under Obsidian only when they change strategy, packaging,
roadmap priority, or forbidden claims.

## Autonomous CEO Actions

Allowed without user approval:

- draft interview guides;
- synthesize public user-problem research;
- maintain assumption registers;
- create outreach scripts for later user approval;
- translate lab artifacts into non-promotional demo/report examples;
- identify missing customer evidence.

Not allowed without explicit user approval:

- contact users;
- send outreach;
- claim product performance;
- build billing, hosted dashboards, or paid subscription infrastructure;
- use customer names or private data in repo artifacts.

## Current Open Assumptions

1. Active crypto traders have a repeated triage pain that is more important than
   another buy/sell indicator.
2. Relative leadership and warning grammar are more valuable as explanation than
   as automated calls.
3. A TradingView companion plus local scanner report is a better wedge than a
   hosted dashboard.
4. Manual, high-touch reports can test value before productizing.
5. The first customers will tolerate research-language caveats if the chart
   prioritization is genuinely useful.
